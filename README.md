## How I Work

I don't just write code — I think about **why** before I write **how**.

Before starting any feature, I ask: What problem does this solve? Who is using it? How will it behave under load? This mindset — borrowed partly from my science background in Biotechnology — means I approach development analytically and systematically, not just mechanically.

**My workflow on every project:**

1. **Understand the requirement** — I don't start coding until I fully understand the goal and the user
2. **Plan the architecture** — schema design, API structure, component hierarchy — all mapped out before writing line one
3. **Build in layers** — database → API → frontend, testing each layer before moving to the next
4. **Write clean, readable code** — because code is read far more than it is written
5. **Deploy and verify in production** — because localhost is not the real world
